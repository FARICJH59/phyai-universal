# Phase 17 — Cryptographic Execution Identity and Evidence

Phase 17 makes the Phase 16 governance result cryptographically bindable to one execution attempt and makes execution evidence and durable receipts fail closed on identity drift or replay.

## Boundary

```text
ControlCommand
    |
    v
HOARE / AEGIS / TCX admission
    |
    +--> capability_id
    +--> lease_id
    +--> fence_id
    +--> attempt_id
    |
    v
ExecutionIdentity
    |
    v
SignedAdmissionArtifact
    |
    v
Physical/HIL execution evidence
    |
    v
DurableReceipt
```

## Execution identity

`ExecutionIdentity` binds:

- tenant ID
- project ID
- command ID
- attempt ID
- artifact hash
- capability ID
- lease ID
- fence ID
- policy digest

The canonical identity is SHA-256 hashed. Changing any bound field changes the identity digest.

## Signed admission artifact

`SignedAdmissionArtifact` carries the identity digest, key ID, algorithm, and signature. `HMACSHA256Signer` is a reference implementation using an injected secret. Secrets are never embedded in source or generated by PHyAI.

The signer is intentionally an explicit cryptographic boundary. Production deployments may inject a stronger asymmetric or hardware-backed signer/verifier without changing the evidence contract.

A signature is accepted only when:

1. the key ID matches;
2. the algorithm matches;
3. the identity digest recomputes exactly;
4. the signature verifies over that digest.

## Evidence binding

`ExecutionEvidence` must bind to the exact admission identity, attempt ID, admission signature, and expected device identity. Rebinding evidence to another attempt or device is rejected.

The capability, lease, and fence are indirectly but cryptographically bound because they participate in the signed `ExecutionIdentity` digest. PHyAI never mints those authorities.

## Durable receipt

`DurableReceipt` is content-addressed from:

- identity digest
- attempt ID
- execution sequence
- result digest

`InMemoryEvidenceStore` provides the reference replay guard. Production deployments should replace it with a durable, transactional store while preserving the same uniqueness invariant.

Duplicate receipt digests are rejected. Receipt construction also verifies its own canonical digest.

## Fail-closed invariants

The following must fail closed:

- tenant/project identity drift;
- artifact drift;
- capability drift;
- lease drift;
- fence drift;
- policy digest drift;
- command/attempt rebinding;
- invalid admission signature;
- evidence/admission mismatch;
- device mismatch;
- duplicate receipt replay;
- malformed receipt digest.

## What is not claimed

Phase 17 does **not** claim a live production HOARE transport, deployed AEGIS/TCX, asymmetric key infrastructure, HSM/KMS integration, or durable production evidence database. Those are integration targets. The repository implements the contract and fail-closed verification boundary without inventing external infrastructure.

The physical execution authority remains outside PHyAI:

> **PHyAI proposes. HOARE governs. AEGIS authorizes. TCX admits. Evidence proves what happened.**
